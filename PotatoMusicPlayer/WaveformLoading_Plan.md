# 波形読み込みの長時間化対策メモ

## 1. 現状の方式

- 方式1(全量先読み): ファイル読込時に `LoadWaveformAsync` (`ViewModels/MainViewModel.cs:512`) が `barCount = 1_000_000` 固定で全曲のピークを1回生成する。ズーム・移動時は再生成せず、`DrawWaveform` (`MainWindow.xaml.cs:705`) が既存データを切り出して描画するのみ。
- 生成中は `WaveformProgressText` に `波形を生成中... N%` と表示するが、波形データ自体は完了時にしか公開されない。
- ボトルネックはバー数ではなくデコード量: 所要時間はほぼ曲長に比例する。数時間の音源では数分単位の待ちが発生しうる。

## 2. 検討した対策

### 案1: 段階表示(着手する)

- 生成途中の部分データを随時公開し、描画も逐次更新する。知覚速度が上がる。
- 土台は既存: `ProgressChanged` 通知、`requestId` による古い要求の破棄がある。データ公開の粒度(例: 進捗通知と同じ間隔)を決めて `CurrentWaveformData` を途中更新する形。
- 未描画の範囲は現行仕様書通り「未表示」でよい(`WaveformZoom_Specification.md` 8章)。

### 案2: ピークのディスクキャッシュ(案1の後に検討)

- ファイルのサイズ+更新時刻(+キャッシュ形式バージョン)をキーに `%LOCALAPPDATA%\PotatoMusicPlayer\` 配下へ保存し、2回目以降は即表示する。
- 古いデータ表示の防止: 読み込み時にキー(サイズ・更新時刻)を照合し、不一致なら再生成する。形式変更時はバージョン不一致で全件無効化する。
- 必要な設定項目(案): 「波形をキャッシュに保存」(オン/オフ)、「キャッシュを破棄」、キャッシュ容量上限。上限超過時は古いものから削除する方針。

### 案3: ハイブリッド / LoD(保留)

- 通常曲は現行方式のまま、長時間(例: 30分超)のみ「粗い全体像を速く+表示中の窓だけ細かく」の二段生成にする。設定の詳細度とは別の粗さレベルを持つ LoD 方式。
- 都度読み(方式2相当)を含むため実装が重い: 圧縮形式のシーク誤差、操作ごとの待ち、非同期キャンセル設計が必要。今回は見送り、将来の設定切替(全量/都度/自動)の受け皿として覚えておく。

## 3. 決定事項

1. まず案1(段階表示)から実装する。
2. 案2はキャッシュ無効化の仕組みと設定項目(保存の有効化・破棄・容量上限)をセットで後続検討する。
3. 案3は保留とする。
