# 中央固定モードの位置・範囲連携 調査結果・修正計画

2026-09-25 のコード調査を反映した修正計画。第3〜6章は実装前の原因・計画を記録し、実施結果は第8章に追記する。確定仕様は [WaveformZoom_Specification.md](WaveformZoom_Specification.md)、アプリ全体は [PotatoMusicPlayer_Specification.md](PotatoMusicPlayer_Specification.md) を参照する。

対象は中央固定モードの追従、シーク同期、波形・ミニマップ描画と、それに必要なコード整理。左流しモードは従来のページ追従・範囲中央軸ズームを維持し、共通処理の変更時に回帰確認する。テーマや波形生成方式の改修は対象外。

## 1. 用語

- **実測再生位置**: 再生エンジンから取得した時刻（秒）。`PlaybackState.CurrentPosition`。通知間隔があるため描画時刻とは一致しない。
- **表示用再生位置**: 実測位置・経過時間・再生速度から補間した時刻。操作プレビュー中・シーク待機中は確定した操作対象位置を優先する計画。
- **表示範囲**: 波形に表示する時間区間 `[S, E]`、幅 `W = E - S`。`WaveformZoomState`。
- **相対割合**: 範囲内での再生位置の比 `r = (P - S) / W`。`r = 0.5` が中央。
- **中央合わせ**: 範囲の中央へ再生位置を合わせる（または範囲の中央へ再生位置が来るよう範囲を動かす）こと。
- **追従**: 再生中に表示範囲を再生位置へ追いかけること。`MainViewModel.UpdateWaveformFollow`。
- **抑止**: シーク適用まで追従を止めること。`_isWaveformFollowSuppressed` と保留シーク（`_isWaveformSeekPending`、`_pendingWaveformSeekPosition`、3秒打ち切り）で管理する。
- **描画キャッシュ範囲**: バー生成時の時間区間。現在の表示範囲とは区別し、表示範囲に合わせて平行移動・再生成するためだけに使う。

## 2. 経緯

以下は当時の意図と変更記録であり、実装がその意図を満たすかは第3章の調査結果を優先する。

1. 当初: 中央固定は「ドラッグ解放で範囲中央から再生」「再生中は範囲を位置へ中央化」の強い中央拘束だった。
2. 範囲外ドラッグ対応: 波形ドラッグのみ、曲の範囲外（空白）へはみ出せるようにした（`PanBeyondEdges`、端が中央に来るまで）。ミニマップは範囲内クランプのまま。
3. 解放ちらつき対策: `SeekAndPlay` をシーク完了まで追従抑止する形に統一した。
4. 全体長補正: 読込時推定と再生実長さの乖離を割合維持で補正するようにした（`ReconcileWaveformDuration`）。再生直後の不安定な実長さには反応しないよう安定待ちを付けた。
5. ミニマップ整備: 再生位置マーカー追加、端余剰の位置付け替え（carry）、端寄せズームの位置軸化。
6. 剛体ペア化: ミニマップ移動は範囲と位置を同量ずつ動かす（相対割合維持）。解放中央シークを廃止した。
7. 割合維持ズーム: 中央固定の全ズーム経路が位置の相対割合を軸にする（`ZoomPreservingRatio`）。中央固定の片側ハンドルは両側ズーム扱いにした。
8. 中央合わせの集約: 再生開始時とシークバー操作時に範囲を位置へ中央合わせする（ミニマップ操作時は行わない）。
9. 追従デッドバンド: 位置が範囲内の中央より左にある間は範囲を動かさず、中央へ追いつくのを待つ。
10. 再生中の `SetPosition` も適用まで追従抑止するようにした。
11. 中央へ向かう向きのミニマップ移動は範囲のみ動かし、中央維持・遠ざかる向きは剛体で動かすようにした。

## 3. 調査結果と確度

対象は未コミットの変更を含む現在のソース。コード追跡と、現行 `WaveformZoomService` をメモリ上で実行した範囲計算の確認を行った。実ウィンドウでの再現、イベントログ採取、修正後の検証は未実施。

### 3.1 共通原因：表示範囲と描画の二重管理

`MainViewModel.UpdateWaveformFollow` は追従抑止・左側デッドバンドを判定し、範囲を曲内に丸める。一方、`MainWindow.PlaybackRendering` はその判定を参照せず、補間位置から毎フレーム `desiredStart = position - width / 2` を計算してバーを平行移動する。描画側は曲外への移動も許す。

したがって、論理範囲を保持しても画面上では中央へ移動する。`_drawnWaveformRangeStart` はバー生成時点の範囲であり、平行移動後の表示範囲ではない。描画キャッシュと論理範囲の再同期だけではこの不一致を解消できない。

### 3.2 問題(1)：初回再生・停止後のミニマップ操作でのちらつき

- 現象：位置は維持されるが、押下中だけ波形が動き、解放すると戻る。
- 主な発生経路：曲長100秒、論理範囲 `[0,20]`、位置2秒なら、描画側は `[-8,12]` 相当にずらす。幅1000pxなら400pxの差になる。操作中の `DrawWaveform()` は変換量ゼロで論理範囲のバーを作り直し、解放後の描画は再び中央へずらす。この座標差は計算で確認済み。
- `MinimapCanvas_PreviewMouseMove` は移動しきい値なしで範囲を更新し、`MoveWaveformRange` は値が同じでも変更通知する。わずかな動き・同じ座標の通知でも再描画へ進み得る。
- 元の候補(a)：再生中の `SetPosition` には抑止が追加済み。ただし描画側が参照していないため対策は不完全。停止・一時停止中の経路は抑止を解除しており、仕様の「再生の有無を問わず適用まで抑止」とも一致しない。
- 元の候補(b)：`PauseForZoomedDrag()` → `BeginManualWaveformNavigation()` の順序が残る。`Pause()` 内の `UpdatePlaybackState()` は Playing→非Playingでも追従するため、抑止前に範囲を変更できる。ただし左側デッドバンドならこの変更は発生しない。
- 確度：上記経路はソースで確認済み。報告された一回の操作でどのイベントが引き金になったかは未確定。範囲外の背景クリックは MouseDown でシークして戻る別経路なので、範囲内部・ハンドル・背景クリックを分けて再現する。

### 3.3 問題(2)：中央外れ状態からの再生

- 左側：`Play()` と `UpdateWaveformFollow()` の保持判定は存在するが、描画側が無条件に中央合わせするため画面では保持されない。「左側保持は実装済み」という従来の記録は論理側に限られる。
- 右側：`Play()` と追従処理が明示的に中央合わせする。挙動自体は実装に沿っており、右側も保持する変更は仕様判断となる。
- 修正対象はまず左側保持と描画の整合。右側の仕様を決めるだけでは共通原因を解消できない。

### 3.4 問題(3)：端寄せズーム前後の表示移動

| 段階 | 確認した要因 | 扱い |
| --- | --- | --- |
| 操作中 | 曲内への丸めで再生位置の相対割合が変わる | 現行仕様が認める端の制約 |
| 操作中 | ハンドル経路が制限前の幅で中心を計算し、その後 `SetVisibleRangeCentered` が幅だけを制限する | 計算不具合として修正 |
| 操作中 | 全体表示では自動一時停止しないため、ハンドルの割合・位置をイベントごとの実測値から計算すると基準が動く | 開始時スナップショットへ統一 |
| 解放時 | 再生位置が範囲外なら近い端へシークする | 現行動作を明示して検証 |
| 解放・再生開始時 | 操作中に休止していた描画側の中央合わせが再開する | 共通原因の修正で解消 |

幅制限の確認例：初期範囲 `[20,40]`、位置25秒（割合25%）、最小幅1秒で0.1秒幅を要求。ハンドル経路では中心25.025秒を先に計算し、最終範囲 `[24.525,25.525]`、割合47.5%になる。`ZoomPreservingRatio` は先に幅を1秒へ制限するため `[24.75,25.75]`、割合25%を保つ。両経路を現行サービスで確認済み。

### 3.5 問題(4)：ミニマップマーカーの更新が滑らかでない

`UpdateMinimapCursor` は実測位置またはドラッグ中の仮位置を参照し、100msタイマー、再生イベント、範囲変更による描画で更新される。`PlaybackRendering` の補間位置を使っていないため、呼び出し回数を増やすだけでは滑らかにならない。さらに更新ごとに子要素を走査し、既存ラインを削除・再生成している。

### 3.6 設計メモと現在のコードの差

- 中央固定の全ズーム経路が `ZoomPreservingRatio` を通るわけではない。ハンドルは MainWindow 内の別計算である。
- `UpdatePendingWaveformSeek` の完了条件から「位置が表示範囲内」の条件は削除済み。旧O8の説明はそのまま適用できない。実長を超える要求、適用失敗、古い通知、3秒打ち切りは別途確認する。
- ミニマップ背景クリックは位置指定、範囲内部押下は移動操作の開始であり、同じ「クリック」という呼び方では原因を切り分けられない。

## 4. 修正後の責務と不変条件

### 4.1 表示範囲を一つの計算経路にする

画面に表示する区間を一つの状態として確定し、波形、範囲ラベル、ミニマップ、座標からのシーク計算が同じ状態を参照する。描画側では再生位置から別の表示範囲を作らない。

| 責務 | 配置・整理方針 |
| --- | --- |
| 実測状態・シーク適用 | `MediaService`。実測値と保留要求を区別する |
| 操作開始・確定・キャンセル、追従方針 | `MainViewModel` と小さな操作状態モデル |
| 範囲・割合・境界計算 | `WaveformZoomService`。WPFやLibVLCに依存しない計算として検証する |
| 時刻の補間 | 独立した小さなクラスへ抽出。現在時刻を渡せる形にし、停止・シーク時のリセットを一元化する |
| フレーム更新 | MainWindow が表示用位置を取得し、ViewModel経由の共通計算で範囲を確定して描画へ渡す |
| バー・カーソル描画 | MainWindow の波形描画用 partial ファイルへ整理。範囲計算や再生制御を持たせない |

100msタイマーとメディアイベントは実測値・補間基準を更新する。再生フレームとイベント処理がそれぞれ異なる位置で範囲を上書きしないよう、連続再生時の範囲更新はフレーム経路へ集約する。停止中の明示操作も同じ範囲計算を呼ぶ。

`ReconcileWaveformDuration` も共通の境界方針を使い、補正時に曲外の範囲だけを曲内へ丸め戻さない。操作中の曲長変更は操作基準と一緒に更新するか、操作終了まで補正を保留する。範囲だけを変更して開始時スナップショットと食い違わせない。

`DrawWaveform` は確定済み範囲を描画し、平行移動量は「描画キャッシュ範囲と確定済み範囲の差」だけから求める。キャッシュが新しい可視部分をカバーしない場合は必要なバーを再生成する。全体を毎フレーム作り直す設計にはしない。

### 4.2 端と保持の方針を明示する

- 幅は `MinZoomLevel <= W <= T`。再生位置・シーク目標は曲内に制限する。
- 自動中央追従・明示的中央合わせ・波形パンでは、曲外の空白を含む区間を表現できるようにする。中央合わせ時の開始位置は `P - W/2`、許容範囲は `[-W/2, T-W/2]`。現在の描画だけのはみ出しを、共有する表示範囲で表す案とする。
- 中央固定のミニマップ移動は曲端が範囲中央に来るまで曲外を許容し、左流しの移動とハンドルのリサイズは曲内に制限する。境界方針を明示した計算APIに分け、汎用メソッドの丸めを一括変更しない。
- 自動追従で曲外を表示しているときのミニマップは、表示範囲と `[0,T]` の交差区間を描く案とする。波形の範囲をミニマップ描画に合わせて変更しない。操作用ヒット領域と実際の時間区間の表示は分ける。
- 曲外範囲からミニマップ操作を始めても、押下だけでは丸め直さない。移動確定後の境界処理とcarryを開始時の状態から計算する。
- 左側デッドバンドでは論理・描画ともに保持する。右側は当面、現行の即中央合わせを基準に検証し、変更は判断事項D1に分離する。

### 4.3 操作状態とシーク待機を整理する

複数のboolが同じ抑止フラグを上書きする構造を整理する。手動操作状態と保留シークは独立して保持し、「手動操作中、または適用待ちなら自動追従しない」を導出する。シーク完了処理が新しい手動操作の抑止を解除しない構造にする。

操作開始時に範囲・再生位置・元の再生状態・入力種別を保存し、**抑止開始 → 必要なら一時停止 → 入力処理**の順にする。押下とドラッグを区別し、しきい値未満では範囲更新・carry・再描画を行わない。終了時は確定位置と再開要否を一度だけ決め、キャプチャ喪失・キャンセル・ファイル切替でも状態を片付ける。

シーク要求は「位置」「再開の有無」「範囲維持／中央合わせ」を明示して共通経路に集める。`SeekAndPlayKeepingWaveformRange` など、名前と効果が重複するラッパーは呼び出し箇所を移行後に整理する。通常再生とドラッグ後の再開は、中央合わせを行うかを明示して区別する。

保留要求には識別子・目標・期限を持たせる。新しい位置操作、停止、曲末、再シーク、ファイル切替で不要になった古い要求を無効化する。停止と一時停止を区別できる実測状態を確認し、停止中に `Time` が適用されない場合も、確定位置を保持して次の再生開始後に適用できるようにする。この再生開始では有効な保留位置を消さない。再生開始を待つ要求と、エンジンへの適用開始後の3秒期限は区別する。失敗・タイムアウト時は実測へ再同期し、抑止が残らないようにする。

表示用位置と補間基準もシーク要求時・適用確認時に更新する。現行の0.5秒許容だけで近距離シークが適用済みと判定されないか確認し、古い通知で目標を巻き戻さない。ドラッグ中の仮位置を実測位置へ書き込まない。

### 4.4 ズーム計算とミニマップ描画を統一する

ハンドル・ホイール・メニューの各経路から共通の割合維持計算を呼ぶ。入力を基準範囲・基準位置・要求幅・境界方針とし、`幅制限 → 割合から開始位置計算 → 端制限` の順を統一する。ハンドル操作では開始時の基準を使い、途中の丸め結果や再生進行を次のズーム基準にしない。

メニューの「範囲を指定して拡大」は、仕様書3.2の割合維持と5.1の範囲中央基準が競合している。計算APIは両方の基準を扱える形にし、この操作の呼び出し方はD4の決定後に移行する。

範囲移動・carryの算術もイベントハンドラから抽出する。現在は開始点からの累積余剰を保留位置へ繰り返し加える形なので、同じ座標の通知で重複加算されないかを検証し、余剰の差分または開始時基準で一度だけ反映する。

ミニマップの波形・範囲オーバーレイ・ハンドル・カーソルを別の描画要素として管理する。カーソルは常設ラインのX座標だけを変更し、波形生成・サイズ・テーマ変更時だけ必要な要素を更新する。再生フレームでは波形と同じ表示用位置を使用し、ドラッグ中はプレビュー位置を優先する。

## 5. 実装順序

以下は実装時に立てた段階計画。現在の進捗と未検証事項は第8章に記す。既存の未コミット変更を基準に作業し、無関係な変更を戻さない。

| 段階 | 作業 | 完了条件 |
| --- | --- | --- |
| P0 再現と基準記録 | 背景・範囲内部・ハンドルを区別し、初回再生／停止後／一時停止後のログを採取する | 問題(1)(3)の押下・移動・解放・再開を識別できる。未再現条件も記録する |
| P1 計算抽出 | 追従判定、境界方針、基準付き割合維持ズームをサービスへ集約する | 左保持、端、幅制限を純粋な計算テストで確認。D1〜D4の未決事項をコードに埋め込まない |
| P2 操作・シーク整理 | 操作状態と保留要求を分離し、抑止を一時停止より先に開始する。各シーク経路と補間リセットを統一する | 古い通知・再シーク・停止・キャンセルでも追従や再開を誤実行しない |
| P3 描画統合 | 描画側の独自中央合わせを削除し、共通の表示範囲に基づく描画・座標変換へ移行する | 問題(1)(2)の論理／描画の食い違いがなく、空白領域・リサイズでも同じ範囲を表示する |
| P4 ミニマップ整理 | ハンドルを共通ズームへ移行、移動しきい値とcarryを整理し、マーカーをフレーム更新する | 問題(3)(4)の検証条件を満たし、毎フレームの子要素再生成がなくなる |
| P5 統合検証・文書更新 | ビルド、計算テスト、手動操作確認。決定した挙動を仕様書へ反映する | 下記受入条件を確認し、実測結果・残件・未検証条件を記載する |

ファイル分割は、責務を確定して呼び出し経路を移行する段階で行う。MainWindow は入力イベントと描画を用途別partialへ分け、コード移動だけで二重計算を残さない。無関係な設定・テーマ処理の全面分割は行わない。

## 6. 検証計画・受入条件

### 6.1 再現ログ

デバッグ時にイベント名、単調増加時刻、操作／要求ID、実測状態・位置、表示用位置、表示範囲、描画キャッシュ範囲、変換量、抑止理由、シーク目標、曲長を記録する。P0では同じ情報を修正前後で比較できるようにする。フレームログは問題区間に限定し、通常再生へ大量出力を残さない。

### 6.2 計算・状態遷移テスト

リポジトリ方針に従い、非UIロジック用の `PotatoMusicPlayer.Tests` を追加する。WPFウィンドウやLibVLC実体を起動せず、時計と実測通知を制御できる形で以下を確認する。テスト用ソースがアプリ側へ取り込まれないプロジェクト配置・Compile設定にする。

| 対象 | 入力と期待結果 |
| --- | --- |
| 左保持 | `[20,40]`、位置25秒は再生開始・フレーム更新とも範囲維持。中央到達後に追従へ移る |
| 右側 | `[20,40]`、位置35秒は現行方針なら `[25,45]`。D1を変更した場合は期待値を明示して差し替える |

## 8. 実装結果と残る検証

- P1・P3：中央固定の追従計算を `WaveformZoomService` と `MainViewModel` に集めた。描画フレームはその結果の表示範囲から波形の移動量を求め、独自の `position - width / 2` を使わない。曲端では共有範囲に空白を含める。波形バーは表示範囲の左右25%も先読みして描き、20%移動した時点で再生成する。

- コード整理：波形・ミニマップの入力と描画を `MainWindow.Waveform.cs` へ移した。再生・ズームの計算はViewModelとサービスへ置いた。

## 9. 動作検証結果
### 意図しない動作
None
### 9.1 上記症状のコード調査と修正

- ミニマップの範囲移動は MouseMove のたびに `MoveWaveformRange`／`PanWaveformRange` を呼んでいた。範囲が端で動かない場合も `ZoomState` の変更通知を出し、操作中は通知のたびに `DrawWaveform()` が全バーを作り直していた。初期の広い表示幅では1回の描画で最大100万サンプルを走査するため、高頻度のマウス移動がUIスレッドを長く占有する。再生バーの更新、再生・停止ボタンの反応が滞る経路をコード上で確認した。
- ドラッグ解放時の `SeekAndPlay` は、既に再生中でも `MediaService.PlayFromPosition` からLibVLCへ `Play()` を再要求していた。この経路はシークだけで足りるため、再生中は時刻の変更のみを行うようにした。
- 範囲移動で実際に開始・終了時刻が変わらない場合は通知しない。変わる場合も、表示幅が一定の移動では先読み済みの波形バーを平行移動し、キャッシュ範囲を超えるときだけ再生成するようにした。
- `dotnet build PotatoMusicPlayer.csproj --no-restore -p:UseAppHost=false -p:OutDir=build-check\\` は警告・エラーなし。`scripts/Test-WaveformZoom.ps1` も成功。実音源による「再生が止まる」「停止でスタックする」の再現・修正確認は未実施なので、LibVLC側に別の要因が残る可能性はある。

### 9.2 同条件で再発した症状の追加調査と修正

- 9.1 の描画負荷対策後も、同じミニマップ範囲移動で再生停止・シークバーの周期的な微動・再生ボタン無反応・停止ボタンの固着が再発した。微動の間隔だけが長くなったため、9.1 の負荷は症状を悪化させていたが、主因の解消には至っていない。
- 範囲オーバーレイの押下時点で `PauseForZoomedDrag` が再生を止め、解放時の `SeekAndPlay`／`PlayKeepingWaveformRange` が再開していた。LibVLC の一時停止・再生状態が通知される前に次の操作へ進むと、ドラッグの速さによって Pause と Play が競合する。この経路は範囲移動に一時停止が必要ないため、範囲移動中は再生を維持し、解放時に必要なら一度だけシークするよう変更した。ハンドル操作の一時停止方針は維持する。
- さらに `MediaService.OnMediaPlaying` は LibVLC のイベントコールバック内で `MediaPlayer.Time` を変更していた。再生開始後に保留シークを適用する処理を UI の同期コンテキスト（ない場合はスレッドプール）へ移し、LibVLC の通知中にプレイヤーを再操作しないようにした。一時停止からの再開時にも位置を Playing 通知後に確定する。停止ボタンがネイティブ処理を待って固まる可能性を減らす。
- ビルドは警告・エラーなし、波形ズームの計算チェックは成功。実音源でのドラッグ・再生ボタン・停止ボタンの連続操作はこの環境で未確認であり、再発の有無は手動確認が必要。

### 9.3 再生動作は概ね正常だが、波形上の再生位置がちらつく

- 実機確認では再生位置と操作は概ね正常になった。一方、再生中にミニマップの表示範囲をドラッグすると、波形上の再生位置の線がちらつく。
- ドラッグ中の仮位置 `_minimapCarriedPosition` は、ミニマップカーソルでは実測・補間位置より優先されていた。しかし波形カーソルの `DrawPlaybackCursorAtCenter(displayedPosition)` は、引数の実測・補間位置を仮位置より先に採用していた。`MouseMove` の仮位置描画と `PlaybackState` 更新の実測・補間位置描画が交互に走り、同じ線を異なるX座標へ動かしていた。
- 波形カーソルも仮位置を最優先に変更した。仮位置がない間は、再生中の描画フレームと同じ補間位置を用いる。ミニマップカーソルとの位置優先順位を揃えた。
- ビルド・計算チェックは成功。ドラッグ中の波形カーソルの実機表示は再確認が必要。

### 9.4 ミニマップで曲外へ続く側の表示

- 曲外に表示範囲が続く場合、ミニマップは曲内との交差部分だけを表示するため、どちら側が曲外か判別しにくい。
- 当初は表示範囲の開始が0未満なら左端、終了が曲長を超えるなら右端に薄いグラデーションを重ねたが、実機では判別しにくかった。

### 9.5 曲外へのミニマップ移動と端表示の修正

- 中央固定でミニマップの範囲を曲外へドラッグしても、初期状態が曲内だと `SetRangeStart` が曲内に丸めていた。再生開始後の `FollowCenterFixed` で初めて曲外を含む位置へ移り、解放直後の範囲表示が再生位置と食い違った。
- 中央固定の範囲移動には `PanBeyondEdges` を使用し、曲端が表示範囲の中央に来る位置までドラッグ中から動かす。マウスがミニマップ外へ出ても移動量を保持する。左流しの範囲移動は従来の曲内制約を使う。
- 曲外へ続く側のハンドルを薄くし、対応する端に外向きの矢印を表示する。矢印は入力を遮らず、既存のテーマ色を使う。

### 9.6 ミニマップの緑枠外からのドラッグ

- 従来の枠外クリックは MouseDown 時に再生位置をシークし、枠をクリック位置へ中央合わせして処理を終えていた。このため、そのままドラッグしても枠はマウスへ追従しなかった。
- 枠外の押下を独立したドラッグ操作として扱う。押下中はマウス位置を仮の再生位置とし、緑枠をその位置へ中央合わせする。再生中も実再生を続け、MouseUp で一度だけ最終位置へシークする。一時停止中は再生を始めず位置だけを設定する。
- マウスキャプチャを失った場合は仮位置を破棄し、操作前の表示範囲へ戻す。
