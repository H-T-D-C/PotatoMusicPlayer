# 再生バーのシーク不具合：進捗メモ

## 目的

`Loop: OFF` で曲を最後まで再生した後、または「次へ」ボタンを押した後に、再生バーで指定した位置から再生できるようにする。

## これまでに確認・変更した内容

- 再生バーのマウス操作完了時に、位置設定と再生を別々に呼び出す処理を `SeekAndPlay` にまとめた。
- `MediaService` に指定位置から再生する処理を追加した。
- LibVLC が停止中・終了状態では時刻変更を受け付けない場合があるため、再生開始イベント後に保留中のシーク位置を適用する処理を追加した。
- 曲終了後に再生ボタン／スペースキーを押した場合は、先頭から再生する既存動作を維持した。
- `dotnet build PotatoMusicPlayer.csproj --no-restore -p:UseAppHost=false -p:OutDir=build-check\\` は警告・エラーなしで成功した。

## 未解決の症状

現時点でも、次の操作では指定位置ではなく先頭から再生される場合がある。

1. 「次へ」ボタンを押す。
2. 再生バーの途中をクリックする。
3. 曲がクリック位置ではなく先頭から再生される。

曲終了後のシークでも同じ症状が残る可能性がある。LibVLC の `Stop`、`Play`、`Playing`、`Time` の非同期な状態遷移と、UI タイマーによる状態更新の競合を追加調査する必要がある。

## 次回調査の候補

- 「次へ」ボタンが実際にはプレイリスト切り替えではなく `Stop` に接続されている点を確認する。
- シーク要求を `Playing` イベントだけでなく、対象メディアの準備完了後に一度だけ適用する仕組みにする。
- `TimeChanged` と `PlaybackStateChanged` のイベント順序をログ出力し、シーク直後に `Time = 0` が書き戻されていないか確認する。
- `SeekBar_PreviewMouseLeftButtonUp` からの要求と、定期的な `UpdatePlaybackState` の更新が同時に走らないようにする。
